# Checking the last theorem argument

In `HABCriterion.lean`, the class-equality proof takes a proof of `HAB.ImultInFOM`. On paper the corresponding result is Corollary 6.3 of Hesse, Allender and Barrington. The theorem argument is visible in Lean. The kernel checks the ensuing implication, both machine compilers, the elliptic-curve descent and the construction of the native verifier. An unconditional Lean proof still needs a construction or separately verified proof of the FOM premise. [Hesse, Allender and Barrington, *Uniform Constant-Depth Threshold Circuits for Division and Iterated Multiplication*](https://people.cs.rutgers.edu/~allender/papers/division.pdf)

## Compare the interfaces

| Published statement | Correspondence in `DiophantineNP/HABTranslation.lean` |
| --- | --- |
| Section 2 describes the bits of the ordinary product of $U$ binary words of $U$ bits each. It allows output indices below $U^2$. | The source proposition quantifies over every Boolean $U$-by-$U$ matrix, interpreted as little-endian input rows, and every pair of output coordinates $h,l<U$. It queries bit $hU+l$ of the product. |
| Section 2.3 uses the finite ordered universe from zero to $U-1$, BIT, an input relation and ordinary first-order quantifiers extended by unary majority. | `HAB.Form` has equality, order, position-first BIT, the binary input relation, Boolean connectives, existential and universal quantification and strict unary majority. `HAB.Form.translate_correct` proves preservation of the semantics by induction. |
| The source returns every output bit. | The project needs the low $U$ bits. `HAB.productTemplate_of_imult` binds $h=0$ and retains $l$. It checks the singleton case directly. There is no legal bit query for $U=0$. |
| Uniformity means a single formula describes the problem. | `HAB.ImultInFOM` quantifies the formula before the universe, all inputs, and the output-bit query. |

Encoding a short output index with two coordinates is the project's explicit presentation of the source convention. It is particularly easy to check in the low-digit case because binding the high coordinate to zero gives the index itself. Quantifier-free input atoms pass through directly. No multiplication on long input rows is built into the source syntax.

## What remains to formalize

The mathematical input cited here is a published theorem. Reproducing its proof in the kernel would supply a closed term of type `HAB.ImultInFOM`. The paper first works with a short modular-power predicate, computes products in Chinese remainder representation using discrete logarithms, converts between residue and binary representations, and removes access to the modular-power predicate in the final uniformity argument. Each reduction must yield one fixed finite formula with the stated semantics. Correctness of a numerical CRT algorithm alone does not exhibit that formula. [Hesse–Allender–Barrington, §§4–6](https://people.cs.rutgers.edu/~allender/papers/division.pdf)

`ShortPower.lean` builds a finite formula and checks its repeated-squaring table under an explicit fit bound on the packed table. `ShortResidue.lean` supplies a majority-based bounded sum over rows and the arithmetic behind multiplication through discrete logs. The checked `ShortResidue.productResidue_spec` computes the residue of an entire iterated product modulo a prime under explicit fit bounds; it handles zero factors too. It takes the factors in residue form. `WidthPrimeResidue.description_correct` instantiates it for the draft’s actual modulus $D_n$. Under the stated table-capacity and row-count bounds, one fixed formula recognizes $D_n$ modulo a prime from the block length and row count. For example, the short-power construction requires $p\leq 2^K$ and $2^{K(K+1)}<U$. Those bounds restrict the available primes. A construction of the full binary product must cover all input widths and justify recovery of its bits from enough residues. `SmallUniverses.lean` proves that a formula valid for all sufficiently large universes can be extended to every finite size by a fixed truth table for the finite exceptions. These are components of the remaining construction. An additional reference develops a variant of the algorithm within bounded arithmetic and is useful for isolating formal subgoals. [Jeřábek, *Iterated multiplication in VTC⁰*](https://arxiv.org/abs/2011.03095)

For a manuscript review, also compare `Classes.D`, `Classes.NP` and `NativeVerifier` with the statements intended in the draft. These specify binary inputs, natural or signed witnesses as appropriate, and the distinctions between unrestricted and bounded soundness. `CoordinateClass.lean` proves that the total-bit bound, the per-coordinate bit bound, and the inclusive numerical bound give the same class. The last convention is Pollett’s on positive inputs. The project includes input zero and assigns it length one. [Pollett, introduction](https://www.cs.sjsu.edu/faculty/pollett/papers/hilbert10.pdf)

## An alternative modulus for the draft’s readout

`BinomialModulus.native_readout` constructs a valid alternative CRT modulus from a power of a central binomial coefficient. `modulus_closed` expresses that modulus using integer powers, division and remainder, and `modulus_bound` bounds its bit length. The corresponding multiplier and scale must still be produced uniformly to replace the general product theorem. This is a separate potential route. The stated theorem `classEquality_of_hab` uses the original width construction.
